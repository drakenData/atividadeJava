Princípios de Design e Arquitetura de Software

Este repositório contém implementações práticas de princípios fundamentais de design e arquitetura de software, desenvolvidos como parte da disciplina de Design e Arquitetura de Software do Bacharelado em Engenharia de Software.

🚀 Visão Geral
O projeto aborda os seguintes princípios e conceitos de design:

DRY (Don't Repeat Yourself): Elimina duplicação de código, promovendo reusabilidade e manutenibilidade
KISS (Keep It Simple, Stupid): Mantém o código simples e direto, evitando complexidade desnecessária
SOLID: Conjunto de cinco princípios de design orientado a objetos

Single Responsibility Principle (SRP)
Open/Closed Principle (OCP)
Liskov Substitution Principle (LSP)
Interface Segregation Principle (ISP)
Dependency Inversion Principle (DIP)



📋 Exercícios Implementados
1. Sistema de Descontos (DRY)
Refatoração de uma classe de cálculo de descontos para eliminar código duplicado, aplicando o princípio DRY.
2. Cálculo de Fatorial (KISS)
Simplificação de um algoritmo de cálculo de fatorial, seguindo o princípio KISS para tornar o código mais eficiente e legível.
3. Validador de Senha (DRY+KISS)
Implementação de um validador de senha que verifica requisitos mínimos de segurança:

Mínimo de 8 caracteres
Pelo menos 1 número
Pelo menos 1 letra maiúscula

4. Calculadora (DRY+KISS)
Desenvolvimento de uma hierarquia de classes para uma calculadora, com:

Classe abstrata base com operações fundamentais
Classe derivada para funções científicas (raiz quadrada, potência)

5. Sistema de Fatura (DRY+KISS)
Implementação de um sistema de fatura para uma loja de informática, com validação de dados e cálculo de valores.
6. Sistema de Veículos (SOLID)
Aplicação completa dos princípios SOLID em um sistema de gerenciamento de veículos:

Classes Motor e Veículo como base
Classes derivadas CarroPasseio e Caminhao
Encapsulamento correto e relações de herança

7. Sistema de Recursos Humanos (SOLID)
Implementação de um sistema de RH com aplicação rigorosa dos princípios SOLID:

Separação de responsabilidades (cálculo salarial, aplicação de aumentos)
Extensibilidade para novos tipos de aumentos
Uso de interfaces e abstrações
Estrutura flexível e modular
